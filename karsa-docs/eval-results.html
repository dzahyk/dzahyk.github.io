What this means

  • The 1.2 rules fixed the classes they were written for and that transferred (lead-definition recall 0.14 → 0.84 on unseen text), but the extractor still does not generalise to new phrasing. That is the expected limit of a pattern list, and it is now measured instead of assumed.
  • Security is the hard blocker: a regex catches the injections it has seen. Injection detection should not rely on the extractor at all; the product already treats brief text as data and grants no permissions from it, and approval stays human (that control is tested separately and is unaffected by these numbers).
  • Next step stays the same and is now better specified: run the Claude provider on dev + v1 + v2 with the same gate (needs ANTHROPIC_API_KEY), and any further rule change must be measured on a new v3 set.
  • v2 labels were written by the same author who revised the rules and have not been adjudicated by a second person. Treat the numbers as the author's measurement, not an independent audit.
